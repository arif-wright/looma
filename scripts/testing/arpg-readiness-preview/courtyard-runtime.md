readiness suite. They do not waive an existing driver, collision, asset, network,
cleanup or image-visibility failure. Source-tree and preservation pins must be
updated from the final exact repository tree before any publication is ready.

## Frame and pixel identity

The existing POST_RENDER observer retains native engine frame IDs, smoothed delta
and the current hero texture/frame/animation only in these dedicated suites.
A requested full probe reads the existing image visibility and a separate vector-
inclusive result. The four legacy observer functions remain byte-identical.
The additional result reads actual owned Graphics command buffers, painter order
including equal-depth ties, transforms, per-fill alpha and decoded source-alpha
samples. Unsupported object/camera effects, masks, alpha or ordering fail closed.
Per-wall/per-fill intersection counts distinguish envelope fade from actual hero
source contributions. Cutaway state and numeric readability may pass with zero
actual hero-source overlap; the report then marks through-wall compositing coverage
unexercised. No native or controlled pose is designated as proving compositing
unless its observed contributing-sample count is nonzero. Envelope fade alone
never proves hero-through-wall compositing.

PNG capture is synchronous `canvas.toDataURL` inside that same POST_RENDER full-
probe branch, after the frame/probe identity is set. There is no later screenshot
API paired with old state and no renderer flag, preserved drawing buffer, canvas
size, render-object or timestep change. Each PNG carries its captured gameplay,
engine frame, hero frame, CSS/backing/logical sizes and evidence mode. One pending
PNG is allowed and is consumed immediately; only bounded metadata history remains.
Each backing side is at most 2,048 px, total pixels at most 2,500,000 and base64
at most 8,000,000 characters (decoded PNG at most 6,000,000 bytes). The decoder
checks CRCs, exact dimensions, zlib output bound and supported RGB/RGBA format.

At both elbow witness poses, the captured camera projects all four world regions
(x1725/1731, y858/873) into the visible art band. Four 5×5 backing-pixel regions
are retained for review. Antialiasing/edge mixing remains explicit; no arbitrary
RGB equality, geometry enlargement or opacity-only hero claim is used. Native
PNG review is still required, even if numeric source transmission is readable.

Source observation limits: 256 world objects, 512 renderer entries and exact
per-object command counts: west foundation 507 (25 fills), east foundation 347
(17 fills), west upper 1,827 (91 fills), east upper 1,187 (59 fills). These are
192 opaque stone/mortar partition quads in total, with no support underlay.
Unknown names, missing/excess commands and unsupported grammar reject the evidence;
the independent graphics contract also checks every color, alpha and coordinate.
Other bounds remain 4,194,304 pixels/source frame, 33,554,432 decoded source
pixels/probe and 16,384 candidate hero samples. Every observed fill contributes
separately to source transmission. Shared partition edges are conservatively
inclusive, so exact seam samples can count adjacent cells more than once. This
diagnostic does not establish raster-edge equivalence; native PNG review remains
required. The original overlap between physical faces/caps still compounds.
